## Purpose

为 Voicebox 的每次语音识别保留可追溯到原始音频位置的分段文本，并允许用户从捕获详情导出稳定、可读且不受精修影响的时间戳文稿。

## ADDED Requirements

### Requirement: 每次成功转录都提供原始时间戳文稿

系统 SHALL 在每次成功的直接转录、捕获创建和捕获重新转录中，同时返回原始全文、格式化的原始时间戳文稿以及结构化分段；每个分段 MUST 包含非负的开始毫秒、结束毫秒和未经精修的文本，结束时间不得早于开始时间，分段顺序 MUST 与音频播放顺序一致。

#### Scenario: 新建捕获完成转录
- **WHEN** 用户通过听写、录制或文件导入创建捕获且 Whisper 转录成功
- **THEN** 捕获结果同时包含 `transcript_raw`、非空的 `transcript_timestamped` 和非空的原始时间戳分段
- **AND THEN** 时间戳分段覆盖识别出的原始语句且按开始时间升序排列

#### Scenario: 直接调用转录接口
- **WHEN** 调用方通过 `/transcribe` 成功识别音频
- **THEN** 响应保留现有 `text` 和 `duration` 字段，并额外返回格式化时间戳文稿及结构化分段
- **AND THEN** 只读取现有字段的调用方仍可正常工作

#### Scenario: Large 与 Turbo 使用相同 API 契约
- **WHEN** 调用方分别以 `model=large` 和 `model=turbo` 调用 `/transcribe`
- **THEN** 两种模型的成功响应都包含不变的 `text`、`duration` 和新增的 `timestamped_text`、`segments`
- **AND THEN** 静态 OpenAPI、生成的桌面端 API 类型和公开示例均将上传字段声明为 `file`，并将 Turbo 的 API 参数声明为 `turbo`

#### Scenario: Whisper 未产生有效时间戳
- **WHEN** 识别后没有任何包含有效起止时间和文本的分段
- **THEN** 系统不得伪造全时长或平均分配的时间轴
- **AND THEN** 本次转录不得作为成功的带时间戳结果保存

#### Scenario: 短音频分段越过推理填充窗口
- **WHEN** Whisper 对不足 30 秒的音频返回了超过真实音频总时长的分段末端或完全位于总时长之后的填充分段
- **THEN** 系统将末端限制在真实音频总时长并丢弃完全位于音频之后的分段
- **AND THEN** 系统不修改仍在音频范围内的模型分段起点与原始文本

### Requirement: 原始时间戳与精修内容相互独立

系统 SHALL 将时间戳绑定到 Whisper 产生的原始文本；Qwen 精修只能生成或替换精修文本，不得修改原始全文、原始分段的文本或起止时间。

#### Scenario: 精修带时间戳的捕获
- **WHEN** 用户对已经具有时间戳分段的捕获执行精修或重新精修
- **THEN** 系统只更新精修文本及精修元数据
- **AND THEN** 原始全文、格式化时间戳文稿和每个分段的起止时间与精修前完全一致

#### Scenario: 重新转录已有捕获
- **WHEN** 用户选择模型或语言重新转录已有捕获且识别成功
- **THEN** 系统以同一次识别产生的新原始全文和新时间戳分段原子替换旧数据
- **AND THEN** 系统清除基于旧原文生成的精修文本

#### Scenario: 重新转录失败
- **WHEN** 已有捕获的重新转录失败或结果缺少有效时间戳
- **THEN** 系统保留该捕获原有的原始全文、时间戳分段和精修文本，不得保存半成品

### Requirement: 捕获记录持久化时间戳分段

系统 SHALL 将原始时间戳分段作为捕获记录的一部分持久化，并在捕获列表与详情响应中提供可选的结构化分段和派生的格式化时间戳文稿。

#### Scenario: 应用重启后读取新捕获
- **WHEN** 应用重启并再次读取此前成功转录的新捕获
- **THEN** 返回的原始分段文本和毫秒级起止时间与保存时一致

#### Scenario: 升级后读取旧捕获
- **WHEN** 用户升级应用并读取升级前没有时间戳字段的捕获
- **THEN** 旧捕获仍可显示、播放、复制、精修和使用原有导出功能
- **AND THEN** 其时间戳分段与格式化时间戳文稿为空，不得根据总时长推测生成

### Requirement: 导出带时间戳的原始文稿

系统 SHALL 在捕获详情的“导出”菜单中提供“带时间戳文稿”操作，并将当前捕获的原始时间戳分段导出为 UTF-8 `.txt` 文件。每个非空分段 MUST 独占一行并使用 `[HH:MM:SS.mmm --> HH:MM:SS.mmm] 原始文本` 格式；导出内容不得使用精修文本替换原始文本。

#### Scenario: 导出具有时间戳的捕获
- **WHEN** 用户在捕获详情选择“带时间戳文稿”、选择保存位置且当前捕获具有有效分段
- **THEN** 系统写入名为 `capture_<短ID>_timestamped.txt` 的文本文件
- **AND THEN** 文件中的行数、顺序、起止时间和文本与捕获的原始分段一致

#### Scenario: 精修视图下导出
- **WHEN** 用户当前正在查看精修文本并选择“带时间戳文稿”
- **THEN** 导出的仍是 Whisper 原始分段文本及其原始时间戳

#### Scenario: 旧捕获没有时间戳
- **WHEN** 用户对没有时间戳分段的旧捕获选择“带时间戳文稿”
- **THEN** 系统不打开保存对话框、不生成空文件或伪造时间轴
- **AND THEN** 系统提示用户可通过重新转录生成时间戳文稿

#### Scenario: 用户取消保存
- **WHEN** 用户在保存对话框中取消操作
- **THEN** 系统不写入文件且不显示成功提示

#### Scenario: 文件写入失败
- **WHEN** 目标路径不可写或文件写入失败
- **THEN** 系统显示导出失败提示并保留当前捕获数据

### Requirement: 现有导出功能保持兼容

系统 SHALL 保持音频 WAV、普通文字稿 TXT 和 Markdown 导出的现有行为；新增时间戳文稿不得改变这些格式选择的内容来源或文件名规则。

#### Scenario: 导出普通文字稿
- **WHEN** 用户选择现有“文字稿 (TXT)”操作
- **THEN** 系统继续导出当前规则选择的精修全文或原始全文，不添加时间戳

#### Scenario: 导出 Markdown 或音频
- **WHEN** 用户选择现有 Markdown 或音频导出操作
- **THEN** 系统继续按原有格式生成文件，不受时间戳文稿功能影响
