## Why

Voicebox 当前每次识别只保留一份不带时间轴的原始全文，无法让调用方准确定位语句，也无法从“捕获”详情导出可用于剪辑、字幕校对或内容复核的时间戳文稿。需要在识别产生文本的同时保留模型生成的原始分段时间轴，并让用户可以直接导出。

## What Changes

- 每次新建捕获、重新转录和直接调用 `/transcribe` 时，除原始全文外，同时产生按语音识别分段组织的开始时间、结束时间和原始文本。
- 在捕获记录中持久化带时间戳原始文稿，并通过捕获详情 API 返回；精修只更新精修文本，不改写原始文本及其时间戳。
- 在捕获详情页“导出”菜单增加“带时间戳文稿”选项，导出 UTF-8 文本文件，每段使用稳定、可读的起止时间格式。
- 旧捕获记录继续正常展示；没有时间戳数据时不伪造时间轴，导出入口给出明确不可用状态，用户可通过重新转录生成。
- 保持现有音频、纯文字稿和 Markdown 导出行为兼容。
- 同步公开 API 示例、静态 OpenAPI 文档与生成的桌面端 API 客户端，明确 multipart 字段名为 `file`、模型参数值为 `turbo`，并暴露新增的时间戳字段，避免调用方因旧契约丢弃数据。

## Capabilities

### New Capabilities

- `timestamped-transcripts`: 定义转录时间戳的生成、持久化、API 契约、原始内容保护和捕获详情导出行为。

### Modified Capabilities

无。

## Impact

- Voicebox 后端语音识别抽象、MLX 与 PyTorch Whisper 实现、`/transcribe` 和捕获相关接口。
- 捕获数据库模型与兼容迁移，以及捕获创建和重新转录服务。
- 桌面端 API 类型、捕获详情页导出菜单、文件保存和中英文文案。
- 后端单元与集成测试、前端类型检查和导出格式测试。
- README、开发者转录指南、静态 OpenAPI 文档和生成的桌面端 API 类型。
- `/transcribe` 响应新增可选 `segments` 字段，现有只读取 `text`、`duration` 的调用方保持兼容。
