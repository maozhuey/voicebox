# 修复语音生成终态丢失

## Why

一次 Qwen 1.7B 合成在已完成第 1/3 段后结束，历史记录仍停留在进行中。任务队列只能把这类记录改写为泛化的“生成被中断”，前端进一步展示为“生成过程中发生错误”。这既掩盖了实际故障边界，也让用户误以为每次都是模型加载或推理失败。

现有队列不会在正常执行中自行取消任务：取消、超时和服务关闭各有独立路径与不同原因。已保存的 macOS 崩溃报告同时证明，历史上存在 MLX/Metal 原生层 `SIGSEGV`，它会终止整个本地服务进程；这与“运行器协程正常返回但没有发布终态”是两类问题，不能再共用同一条中断文案。前者需要由桌面端监督服务生命周期并让启动恢复保留异常退出原因，后者需要修正后端队列与生成运行器的终态交接。

生成任务需要一个明确且可验证的终态契约：完成、模型异常、取消、超时以及“运行器返回但未发布终态”必须彼此可区分；队列不得覆盖已经持久化的真实结果。对于最后一种内部状态不一致，系统还需要留下不含文本内容、文件路径或堆栈的本地诊断，才能定位究竟停在第几段及哪一类状态转换。

## What Changes

- 为生成运行器与任务队列定义显式的终态交接：每个任务离开运行器时必须已经发布终态，或由队列以可识别的“终态未发布”原因失败。
- 为桌面端本地服务增加一次运行生命周期标记：服务正常关闭、父进程主动停止和异常退出必须可区分；服务重新启动时，将未完成任务标记为对应的可重试失败，而不是笼统的“中断”。
- 对已完成、已取消、已超时或已因推理异常失败的任务保留原始终态；队列兜底不得再无条件覆盖这些结果。
- 当运行器在记录仍为加载中或生成中时正常返回，保存一个脱敏的本地生成诊断，包含引擎、模型、当前分段/总分段、运行器退出类别和诊断编号；历史记录引用该稳定编号。
- 客户端识别该稳定错误标识，提示合成在哪个分段中断及可重试，而不是展示无上下文的“生成过程中发生错误”。
- 增加覆盖三段生成、状态写入失败、取消、超时、正常完成和队列继续消费后续任务的后端与客户端回归测试。

## Capabilities

### New Capabilities

- `generation-terminal-status`: 保证语音生成任务发布且保留可追溯的终态，并向用户提供安全、可行动的失败信息。

## Impact

- 涉及后端生成运行器、任务队列、生成历史状态写入和本地诊断记录，以及桌面端对本地服务生命周期的监督。
- 涉及前端生成错误信息映射；不改变引擎选择、请求参数或已有历史数据结构的公开接口。
- 新增后端单元/集成测试和客户端错误映射测试；现有取消、超时和任务恢复测试需保持通过。
