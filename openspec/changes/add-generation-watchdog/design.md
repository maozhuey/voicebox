## Context

当前 `task_queue` 以单一 worker 串行执行协程，只在协程返回、取消或抛异常后才处理下一项。`run_generation` 会将自身异常转换为失败状态，但不能处理底层推理调用永久不返回的情形。项目已有模型加载时限配置；本变更不改变该配置的职责，而是为整个已运行生成任务建立独立看门狗。

## Goals / Non-Goals

**Goals:**

- 给每条已运行生成任务施加统一、可配置、有安全默认值的运行时限。
- 超时后可靠取消协程、持久化失败状态、清理活动任务并推进下一条队列任务。
- 用确定性的异步测试验证超时恢复和正常执行路径。

**Non-Goals:**

- 不终止或重启整个 Voicebox 服务。
- 不尝试强杀无法响应系统取消的底层原生线程或模型进程。
- 不修改生成 API、音频分段算法或已存在的模型加载超时语义。

## Decisions

### 在队列 worker 外层等待单个任务的完成时限

使用 `asyncio.wait_for` 包裹 worker 创建的单个任务；超时时该 task 会收到取消请求，worker 随后清理运行态并进入下一轮取队列。与在各后端或每个分段单独加时限相比，这能覆盖模型加载后的所有不可返回阶段，也不要求修改各 TTS 后端。

替代方案是在 `run_generation` 内包裹推理调用。该方案遗漏模型准备、文件持久化或未来新增生成阶段，并会让队列恢复逻辑分散，故不采用。

### 将超时状态写入统一的失败恢复路径

看门狗在接收到超时时调用现有的失败状态恢复函数，写入固定、不包含实现路径或底层异常的错误提示。`run_generation` 仍负责其自身 `CancelledError` 的数据库更新和活动任务清理；看门狗的失败写入须保持幂等，以兼容两侧的完成先后顺序。

替代方案是仅取消协程并依赖生成协程落库。该方案在协程无法进入异常处理或状态写入失败时会重新出现悬挂状态，故不采用。

### 采用本地环境变量提供默认时限

在 `backend/config.py` 添加与现有模型加载时限相同的校验模式：默认值足以完成正常长文本合成，非法或非正值回退默认值。默认值与变量名称将在实现和测试中固定，便于桌面包与本地 Docker 通过启动环境调优，无需新增设置页面或 API。

## Risks / Trade-offs

- [极慢但合法的长文本生成被超时取消] → 采用相对保守的默认值并允许本地覆盖；保留现有分段设置，用户可重试。
- [底层原生推理不响应 asyncio 取消] → Python 协程能释放时继续队列；若运行时无法协作取消，失败记录仍须可见，后续将作为模型运行时隔离议题处理。
- [超时与生成协程的失败写入竞争] → 仅对仍处于活动状态的记录做幂等更新，并以回归测试覆盖最终状态与队列推进。

## Migration Plan

1. 增加配置读取、看门狗与测试后，在本地开发服务运行定向测试。
2. 使用本地 Docker 环境验证超时后后续生成可被接收并执行；不部署线上环境。
3. 若出现意外误超时，将环境变量设置为更高值后重启服务即可回退，无需迁移数据库或改动已有生成记录。
