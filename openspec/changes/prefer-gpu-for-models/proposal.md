## Why

部分在 Apple Silicon 上运行的语音模型被显式固定到 CPU，即使系统的 GPU 可用；同时，模型加载没有统一的超时和离线缓存保护，底层加载器异常等待时会让生成任务永久停留在“加载模型中”。

现在需要让所有支持的本地模型优先使用可用 GPU，并让无法完成的加载以可理解的失败状态结束，避免用户无限等待。

## What Changes

- 统一模型设备选择策略：在兼容的运行环境中优先选择 GPU；Apple Silicon 上优先使用 MLX 或 PyTorch MPS，其他平台保留 CUDA、ROCm、XPU 与 DirectML 优先级。
- 为因已知兼容性而不能稳定使用 GPU 的后端提供运行时回退机制：GPU 加载或首次推理失败时，释放失败实例并以 CPU 重试，而不是预先固定为 CPU。
- 为模型加载增加可配置超时；超时后将关联生成任务更新为 `failed`，写入面向用户的错误说明并释放队列。
- 已完整缓存的模型加载必须使用本地缓存，避免为元数据检查无限等待远端服务；缓存不完整时仍保留可观测的下载流程与失败信息。
- 补充后端设备选择、缓存优先、加载超时、失败状态与队列恢复的自动化测试。

## Capabilities

### New Capabilities

- `model-runtime-resilience`: 定义本地模型的 GPU 优先选择、CPU 回退、缓存优先加载与加载失败终态行为。

### Modified Capabilities

- 无；仓库当前没有已建立的 OpenSpec 主规格可修改。

## Impact

- 后端：`backend/backends/base.py`、各 TTS 后端、模型加载编排与生成队列。
- API：生成记录的失败状态与错误信息将更及时、明确；不改变请求参数或成功响应结构。
- 配置：新增模型加载超时配置，并提供安全默认值。
- 测试：新增设备策略和超时/缓存回归测试；既有生成、取消和模型端到端测试需保持通过。
