## Context

参见 `proposal.md`。当前默认 Qwen TTS、Whisper 和 Qwen LLM 在 Apple Silicon 上会选择 MLX，但多项 PyTorch TTS 后端通过 `force_cpu_on_mac` 或未启用 `allow_mps` 固定使用 CPU。模型加载由异步队列编排，但底层同步加载器可访问远端仓库，且没有统一时限；已缓存模型也可能进行远端元数据检查。

## Goals / Non-Goals

**Goals:**

- 将设备选择收敛成一个 GPU 优先、可报告、可测试的策略。
- 对所有当前本地模型提供“GPU 首选，失败一次后 CPU 回退”的一致行为。
- 限制单次模型加载的等待时间，保证生成任务和队列一定进入终态。
- 在缓存完整时阻止远端元数据查询成为加载路径的依赖。

**Non-Goals:**

- 不新增云端推理或改变模型下载来源。
- 不承诺所有上游模型在 MPS 上都无缺陷；不兼容时以 CPU 回退保证功能可用。
- 不修改已有生成 API 的请求或成功响应格式。
- 不在本次变更中重新设计模型管理界面。

## Decisions

### 统一设备偏好与运行时回退

新增共享的设备选择与回退契约：所有 PyTorch 本地推理后端先选择可用加速器，Apple Silicon 允许选择 MPS。取消针对 macOS 的预先 CPU 强制策略；保持每个后端对不兼容算子的必要初始化配置。

模型加载或首次推理在 GPU 上失败时，后端清理模型与设备缓存、记录诊断日志，并仅以 CPU 重试一次。这样既满足“优先 GPU”，也不把已知上游 MPS 不稳定性暴露为用户无法恢复的失败。

备选方案是在兼容性已知不佳的后端继续硬编码 CPU。该方案不满足本次 GPU 优先目标，且无法获知上游版本改善后的可用性，故不采用。

### 在编排层施加加载时限

在所有经 `load_engine_model` 进入的生成路径外层施加可配置的异步等待时限，默认值定义在后端配置模块并允许通过环境变量覆盖。超时将转换为稳定的领域错误，由既有 `run_generation` 异常处理写入失败状态并完成任务管理器记录。

选择编排层而非为每个第三方加载器分别实现计时，因为它覆盖所有模型引擎，并能确保生成队列在异常时推进。底层 `asyncio.to_thread` 本身不能强制终止第三方线程，因此超时后会隔离该次调用、不复用不确定的实例，并限制并发加载以避免竞态。

### 缓存完整时启用严格本地加载

复用现有完整性检测结果，将“模型所需权重与配置齐全”转换为加载器的本地文件优先参数或本地快照路径。缓存不完整时保留当前可观测下载机制。此策略避免已下载模型在网络受限、代理异常或远端慢响应时无限等待。

备选方案是进程级强制离线模式。它会影响并发下载和其他模型加载，项目已有注释说明这种全局切换曾造成回归，故不采用。

### 面向用户的稳定错误

超时与设备回退失败生成简短、可操作的中文错误文本；详细异常仅写服务日志。历史记录和 SSE 仍使用现有 `failed` 状态，以保持 UI 和重试功能兼容。

## Risks / Trade-offs

- [部分上游模型在 MPS 首次推理才失败] → 将首次推理纳入一次性 CPU 回退，且不重复无限重试。
- [超时无法终止底层线程] → 使请求和队列先进入终态，隔离失败实例，并在后续加载前同步后端状态。
- [离线缓存判定遗漏必要文件] → 使用每种模型现有的必需文件检测，并加入“完整缓存、网络不可达”回归测试。
- [GPU 内存不足] → 视为 GPU 失败并触发一次 CPU 回退；保持串行生成以避免 GPU 竞争。

## Migration Plan

1. 增加配置默认值与共享加载包装，不修改数据库模式。
2. 逐个迁移后端到共享 GPU 优先/回退契约，并加入单元测试。
3. 将生成路径接入加载时限与稳定错误，再运行既有队列、生成和端到端回归测试。
4. 在本地 Docker 环境启动后，以完整缓存但禁用远端访问的条件验证加载与超时失败状态。
5. 回滚时恢复原有设备选择与加载包装；生成记录仍使用既有状态字段，无需数据迁移。
