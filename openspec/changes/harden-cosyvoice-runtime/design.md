## Context

CosyVoice 3 的上游模型在 macOS 上仅选择 CUDA 或 CPU；Voicebox 的 TTS 后端缓存允许 Qwen/MLX 与 CosyVoice 同时常驻。CosyVoice 的非流式路径会在内部线程上进行自回归解码，并以无时限的 `join()` 等待结果；`asyncio` 取消不能终止该线程。相关行为契约见 `specs/cosyvoice-runtime-stability/spec.md`。

## Goals / Non-Goals

**Goals:**

- 每次 CosyVoice 生成开始前让其他 TTS 模型不再占用运行时和 Metal 缓存。
- 让每个 CosyVoice 文本分段能够在确定时限后被真正终止，而不是仅取消等待它的协程。
- 将当前阶段和阶段耗时作为兼容的任务状态数据保存，用于历史查询和 SSE 轮询。
- 只在自然语义边界拆分 CosyVoice 文本，并保留自然朗读停顿；不引入固定字符数上限。

**Non-Goals:**

- 不实现或宣称 CosyVoice 的 MPS/Apple GPU 支持；该上游版本仅使用 CUDA 或 CPU。
- 不改变用户明确保留的界面/请求引擎选择行为。
- 不修改模型文件、模型缓存目录、声音档案格式或非 CosyVoice 的生成语义。

## Decisions

### 在 CosyVoice 加载前集中卸载其他 TTS 后端

新增一个只针对 TTS 后端缓存的资源协调入口，并为每次 TTS 推理持有可计数的执行租约。CosyVoice 在获取租约前，必须等待其他引擎的活动租约归零；随后遍历已实例化的其他空闲 TTS 后端，调用其卸载契约，再执行垃圾回收；MLX 后端额外释放 Metal 缓存。所有常规生成、流式试听与预设声音试听都通过该入口，以避免绕过队列的请求卸载正在运行的模型。该入口不触碰 STT 或本地 LLM，以避免扩大用户可见的模型切换范围。

替代方案是由每个后端自行猜测何时回收其他模型。该方案会让资源所有权分散，也无法保证 CosyVoice 加载前已完成回收，因此不采用。

### 将 CosyVoice 推理放入可终止的专用工作进程

父服务通过一个仅服务 CosyVoice 的工作进程执行每个有界分段。工作进程拥有上游模型和其内部线程；父服务通过结构化消息接收阶段、音频结果或安全错误。若分段超时，父服务终止并回收该工作进程，清除失效工作器引用，再将该任务写入失败终态。这样可以终止 `thread.join()` 无法通过协程取消的上游线程。

替代方案是继续用 `asyncio.to_thread` 加 `wait_for`。它只能取消等待，无法终止上游线程，已在真实任务中超过 600 秒仍占用队列，不能满足可恢复要求。

### 仅按自然语义边界执行 CosyVoice 分段

CosyVoice 沿用现有自然朗读规划器：段落、句末和强停顿可以形成独立分段；没有这些边界的文本保持为原始单段。每段使用同一声音提示和朗读指令，按顺序拼接。单段异常的风险由可终止工作进程和独立时限处理，而不是以字符数截断用户文本。

替代方案是施加 40 或 100 字上限。用户明确不接受固定字数截断，且字符数不能可靠代表不同语言或标点结构的解码成本，因此不采用。

### 阶段消息为最小、可持久化的诊断数据

工作进程在进入前处理、LLM 解码、Flow 和声码器时发送阶段事件。父服务将最新阶段与各阶段起止/耗时写入生成记录的 JSON 诊断字段，并将安全的阶段名扩展到状态 API/SSE；不记录用户文本、文件路径或堆栈。数据库迁移必须兼容已有 SQLite 数据库，旧记录的字段为空。

替代方案是只写日志。日志在冻结桌面端不稳定且无法随历史任务查询，不能帮助用户确认当前卡点，因此不采用。

## Risks / Trade-offs

- [工作进程首次启动需要重新加载 CosyVoice，增加冷启动时间] → 在同一轮 CosyVoice 生成内复用工作进程；只有超时、崩溃、引擎切换或应用退出时回收。
- [无自然边界的超长文本仍可能触发上游长解码] → 每个原始分段均在独立工作进程和可终止时限内运行；超时后安全失败并释放队列。
- [进程通信传输音频有序列化成本] → 仅传输已完成的单段 float32 音频，分段上限使其大小受控。
- [旧数据库没有诊断列] → 使用幂等 SQLite 迁移和空值兼容响应；不修改既有生成数据。
- [CosyVoice 到达时其他 TTS 正在执行] → 通过活动执行租约等待其自然完成，而非中途卸载；这样优先保证已开始的音频不失败，再进行资源切换。
- [工作进程启动失败] → 父服务写入稳定、可重试的 CosyVoice 错误并释放生成队列。

## Migration Plan

1. 添加数据库诊断字段与迁移、资源协调及进程工作器的单元测试；先验证超时可回收和非 CosyVoice 回归。
2. 接入 CosyVoice 后端的阶段事件、安全分段和任务状态持久化；运行目标测试与完整相关回归。
3. 在隔离数据目录中依次运行 Qwen 后 CosyVoice，确认 Qwen 被卸载、CosyVoice 成功生成，并模拟超时确认后续 Qwen 任务可运行。
4. 构建新的冻结侧车、重新签名并以可回退备份方式替换本机 Voicebox；通过健康接口、CosyVoice 实际生成和历史诊断字段验收。
5. 若本机验证失败，切回当前 `/Applications/Voicebox.app.pre-mlx-thread-affinity-20260907-0040` 备份并保留诊断数据。
